# n8n 2.19.5 REST API Activate Bug 解決方案

> 日期：2026-05-15
> 環境：n8n 2.19.5, SQLite, WSL2

## 錯誤症狀

透過 REST API 激活任何工作流時報錯：

```json
{
  "code": 0,
  "message": "propertyValues[itemName] is not iterable",
  "stacktrace": "TypeError: propertyValues[itemName] is not iterable
    at Object.getNodeParameters (/home/athing/.hermes/node/lib/node_modules/n8n/node_modules/n8n-workflow/src/node-helpers.ts:933:65)
    at new Workflow (/home/athing/.hermes/node/lib/node_modules/n8n/node_modules/n8n-workflow/src/workflow.ts:110:39)
    at WorkflowService._findConflictingWebhooks (...)"
}
```

即使最簡工作流（scheduleTrigger + noOp，僅 2 個節點）也無法激活。

## 觸發條件

任何 POST `/rest/workflows/{id}/activate` 帶有效的 versionId，都會觸發此錯誤。

## 解決方案

直接操作 SQLite 強制設 active=1：

```python
import sqlite3
conn = sqlite3.connect("/home/athing/.n8n/database.sqlite")
c = conn.cursor()
c.execute("UPDATE workflow_entity SET active=1 WHERE id='目標工作流ID'")
conn.commit()
```

設完後需要重啟 n8n 讓 schedule trigger 被正確載入。如果不重啟，n8n 的記憶體中的 workflow cache 可能不會自動更新。

## 相關陷阱

### PUT vs PATCH

n8n 2.19.5 不接受 `PUT /rest/workflows/{id}`（回 404 `Cannot PUT /rest/workflows/{id}`），必須用 `PATCH`。

### executeCommand 節點內含 localhost webhook URL

如果在 executeCommand 節點的 command 參數中包含了 `http://localhost:5678/webhook/XXX` 路徑（例如用 curl 通知本地 webhook），n8n 的 `_findConflictingWebhooks` 方法會掃描**所有節點參數中的字串**，誤判為 webhook 衝突。

**解決方案：** 通知改用 log 檔寫入，或透過外部 Telegram API（不用 local webhook）。

```json
// ❌ 會觸發 webhook 衝突檢測
{"command": "curl -s -X POST http://localhost:5678/webhook/hermes-task-loop ..."}

// ✅ 安全方式（寫 log）
{"command": "echo 'Gateway restarted by n8n' >> /tmp/gateway_restart.log"}
```

## 驗證方法

重啟 n8n 後確認 active 狀態：

```bash
# 確認 workflow active
python3 -c "
import sqlite3
conn = sqlite3.connect('/home/athing/.n8n/database.sqlite')
rows = conn.execute('SELECT id, name, active FROM workflow_entity').fetchall()
for r in rows:
    print(f\"{r[0][:8]} | {r[1]} | active={r[2]}\")
conn.close()
"
```
